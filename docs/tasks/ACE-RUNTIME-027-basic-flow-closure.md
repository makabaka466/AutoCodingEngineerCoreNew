## 4. 发现的基础缺陷与根因

### 4.1 真实 Python 绝对路径被 Verify 拒绝

第一次临时仓库闭环中，修改审批和文件编辑成功；验证审批后，Claude Code 拒绝了
`D:\python\python.exe -m pytest -q`。状态机已经正确进入 `verifying`，根因是
`ExecutionPolicy` 只允许以 `python -m pytest` 等别名开头的命令，没有匹配用户实际批准的真实
Python 绝对路径。

修复：根据当前进程、`pythonw.exe` 同目录和 PATH 解析已经存在的 Python 执行器，只为这些精确
前缀增加 `-m pytest/ruff` 权限；同时兼容 Windows 与正斜杠表示。没有加入任意路径通配符，也没有
开放其他 Bash。

### 4.2 Inspect 把历史 changed_files 误判为本轮写入

验证未运行后续聊时，模型复述了上一轮已经批准修改的 `calculator.py`。旧校验只要在 inspect
看到非空 `changed_files` 就终止任务，混淆“模型描述的历史事实”和“当前轮真实副作用”。inspect
本身没有 Edit/Write/Bash，因此该字段不能证明本轮发生写入。

修复：inspect 轮把这种历史字段清空并写入 `decision_repaired`，不记录模型返回的未校验路径；真实
修改仍由 implement 阶段的 Runtime 工具权限、Git 前后快照和 Patch Artifact 证明。系统提示词也
明确 `changed_files` 只表示当前 Runtime 轮修改。
