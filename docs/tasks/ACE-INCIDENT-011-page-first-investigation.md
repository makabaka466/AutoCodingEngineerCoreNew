## 1. 目标

1. 异常调查必须先获得可信页面名称；名称可由用户文字明确提供，也可由模型从截图的窗口、
   标签页、窗体或页面主标题中提取；
2. 截图不能触发全量页面查询。页面标题不清楚时只询问标题，不扫描全部菜单；
3. 页面映射先执行小范围精确/前缀查询，无结果时才执行有界关键词模糊查询；
4. 模型结合页面名称、映射 URL、当前代码和截图界面特征选择候选，URL 不能直接当成最终代码事实；
5. 文字异常先定位相关代码分支，再提取最小只读 SQL 自动查数；截图异常先识别页面标题与异常区域，
   后续使用相同代码和数据证据链；
6. 通用强制规则、`生物` 项目专属知识、单次诊断产物保持分层，避免全局提示词和长期知识相互污染。

- 异常 Runtime 每轮始终加载项目内置的异常流程 Markdown 规则；

- `knowledge/incident/生物/生物.md` 保留并完善 `Menu.NAME -> Menu.URL` 的项目专属查询方法；
- Prompt 明确页面名称前置条件、截图标题识别、有限候选、截图交叉验证和文字/图片分流；
- `completed` 结构化结果必须包含至少一个已验证的工作区相对源文件；
- 桌面异常输入引导明确要求页面名称，或包含页面标题的截图；
- 非 live 测试、Ruff、编译和 diff 检查通过；版本、README、架构、接口、工程经验同步；
