# ACE-RUNTIME-017：异常查询协议与分阶段预算

## 目标

修复异常调查中SQL Server `@name`参数被宿主拒绝，以及页面定位耗尽统一查询轮次后无法继续查询
业务数据的问题。保持模型负责语义判断、宿主负责只读安全和确定性预算。

## 已确认根因

- 模型第一轮使用`@page_name`，旧绑定器只识别`:page_name`，查询未进入数据库；
- 第二轮精确/前缀查询真实返回0行；
- 第三轮`%良率%`模糊查询在执行前被统一两轮上限拒绝；
- 只读复核证明第三条查询能找到“小米良率数据上传”及其页面URL；
- 业务数据查询尚未开始，因此不是业务表选择错误。

## 实现范围

- Prompt和数据契约明确首选`:name`，参数字典键不带前缀；
- SQL Server宿主安全兼容`:name`与`@name`，保留`@@`系统变量并跳过引用内容；
- `IncidentDecision`新增`page_lookup/business_data`查询阶段；
- 页面定位、业务数据和SQL纠错使用独立预算，默认分别为2、2、1；
- 业务数据查询必须携带已验证页面，模型负责阶段判断，宿主不按表名猜测；
- 查询审计和桌面UI展示阶段、成功/失败及脱敏错误；
- 保留只读校验、60秒超时、100行默认上限、脱敏和不保存原始业务行的边界；
- 旧异常会话载入时根据已有页面信息推导旧`query_required`决定的阶段。

## 验收标准

- `@name`、`:name`可在同一SQL中安全绑定，`@@ROWCOUNT`和字符串中的`@name`保持原样；
- “精确页面0行→模糊页面命中→业务数据查询”三次成功查询可以完整执行；
- 一次SQL失败可自动纠错，并留下失败及成功两条审计摘要；
- 页面查询不会消耗业务查询额度，失败不会消耗成功查询额度；
- 非live测试、Ruff、compileall和diff检查通过；
- 发布`v0.7.4`并向GitHub推送一次。

## 验证结果

- 针对性回归：54项通过；
- 完整非live回归：192项通过；
- Ruff、compileall与`git diff --check`通过；
- 未执行任何写数据库、修改MES源码或调用真实业务接口的测试。
