# ACE-RUNTIME-022：分阶段搜索纠正与真实异常验收

## 1. 问题

v0.7.8 对整个异常命令只允许一次搜索参数纠正。真实长流程在源码追踪阶段纠正成功、继续完成 SQL
调查后，如果后续独立源码阶段再次漏传 `glob/type`，仍会因总预算耗尽而提前失败。

## 2. 实现

- 开发与异常 Engine 改为记录连续搜索违规次数；
- 任意通过 Runtime 和结构化契约校验的决策都会重置当前违规链；
- 后续独立调查阶段可以各获得一次有界纠正；
- 连续第二次违规、路径越界和预算超限仍然失败；
- 增加两段独立“阻断后纠正”的异常流程回归测试。

## 3. 真实验收

- 使用小米良率上传日志缺失问题执行完整异常流程；
- 完成 Menu 精确/模糊定位、限定源码调查、SQL Server 只读查询和诊断沉淀；
- 会话 `38e7af0e-c777-45d8-bb80-ad9c78493b44` 状态为 `completed`；
- Event Store 保存 6 次 Runtime Run、17 组只读工具事件、4 个查询批次和 1 次策略纠正；
- 没有授权或执行 MES 源码写入、数据库写入与外部上传；
- 发布 v0.7.9 并推送 GitHub。
