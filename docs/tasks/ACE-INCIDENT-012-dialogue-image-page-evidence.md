## 1. 目标

1. 有图片时先理解用户对话中的页面标题、页面路径和上下文，再查看图片识别可见页面标题；
2. 图片没有明显标题但对话提供标题时，以对话标题进行有界页面映射，再把候选页面与图片特征
   交叉验证；
3. 映射或代码与图片存在实质冲突且模型无法消解时，询问用户确认哪个页面发生异常；
4. 有界精确/前缀与模糊查询都没有可信结果时，询问准确标题、菜单入口或页面路径；
5. 对话和图片都没有可靠页面线索时直接澄清，不扫描全部菜单；
6. 无图片时，对话中的页面标题或页面路径任一项可作为调查起点；两者都没有时再询问；
7. 所有标题提取、路径语义、截图匹配和冲突判断由模型完成，不新增 OCR、关键词、颜色、文件名
   或字符串相似度硬编码。

## 2. 验收标准

- 内置异常 Markdown 明确“先对话、再图片”的证据顺序，并覆盖有图/无图分支；
- 页面标题不再是唯一允许的调查入口，可信页面路径可以直接进入代码验证；
- 图片无标题时允许使用对话标题查询并与图片交叉验证；
- 查询无结果、图片与候选冲突或线索不足时返回 `needs_input`；
- 生物项目继续保留两阶段、最多 20 条的 `Menu` 查询，不引入全表扫描；
- `completed` 仍要求至少一个已验证页面源码路径；
- 桌面文案提示用户提供页面标题或路径，也允许粘贴截图；
- 非 live 测试、Ruff、compileall、wheel 资源和 diff 检查通过；
- 更新版本至 `0.6.3`，提交、创建 `v0.6.3` 标签并推送远端。

## 3. 关键决策

- 决策：上一版“可靠页面名称是所有调查的强制前置”过于绝对。本次由“页面身份证据足够”替代，
  标题和路径都是模型可判断的入口；
- 决策：对话内容先于图片分析，避免图片只有局部异常区域时忽略用户已经明确提供的标题；
- 决策：流程规则描述推理顺序和证据门槛，不由宿主实现文本/图片分类器；
- 决策：宿主继续只校验 completed 必须包含已验证源码路径，并维持 SQL 权限、限行、超时和脱敏
  等确定性边界。

## 7. 剩余边界

- 当前没有 OCR 服务、候选评分或专门的页面冲突事件；模型理由主要记录在结构化页面说明和事件中；
- “对话标题”“可信路径”“图片明显标题”和“实质冲突”均由模型判断，不保证所有兼容模型具有相同
  视觉能力；
- 推荐联调样本：无图只有标题、无图只有路径、有图且证据一致、图片无标题但对话有标题、图片有
  标题但对话无线索、候选与图片冲突、两阶段查询无结果。
