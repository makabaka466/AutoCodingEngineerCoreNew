# ACE-RUNTIME-028：异常调查深度适配与剩余基础验收

## 1. 状态

- 状态：`done`
- 开始时间：2026-09-07
- 完成时间：2026-09-07
- 用户目标：优化真实验收中暴露的过度调查、页面误判和搜索策略误拦截，并继续完成基础流程验收。
- 安全范围：目标 MES 项目只读；SQL Server 只执行有界参数化 SELECT；没有修改业务代码、数据库或
  外部系统。真实开发写入仍只使用上一迭代的临时 Git 仓库结果。

## 2. 本轮问题

用户只要求确认页面代码位置时，旧 `IncidentDecision` 仍强制填写 `diagnosis`。模型因此继续追踪
业务代码、尝试形成根因和解决方案，造成范围扩大、Token 增长以及无证据结论。真实验收还发现：

1. `**/CKClient/**/*.cs` 已限定业务子目录，却被递归扩展名规则误判为全项目扫描；
2. 只使用连续词“良率上传”会命中 `FCModelUpload`，丢失“小米”这一独立身份线索；
3. 模型可能把候选正式标题与用户标题不一致解释成别名，页面映射存在误判风险；
4. 页面定位阶段整篇读取业务文件，携带了完成身份验证并不需要的上下文。

## 3. 实现

### 3.1 调查深度由模型选择，完成契约由宿主校验

新增 `IncidentCompletionKind`：

- `page_location`：只定位并验证页面、菜单路由和工作区相对源码；
- `diagnosis`：追踪异常因果、按需查询业务数据并给出解决方法。

这不是关键词分支。模型根据当前对话语义选择本轮深度；宿主继续校验完成状态必须有页面和源码。
`page_location` 不要求诊断与建议，完成消息只显示页面定位、代码位置和定位依据；`diagnosis` 继续
显示结论、异常原因、解决方法和置信度。同一会话续聊会保留完成类型：页面定位后若用户新增根因
问题，紧凑路由必须升级为完整调查，不能用页面身份冒充诊断证据。

### 3.2 最小页面身份证据门槛

`LocatedPage` 新增：

- `matched_evidence`：最多六项相互独立的当前证据；
- `unresolved_conflicts`：最多四项仍未解决的标题、路由、截图或源码冲突。

模型负责判断什么构成匹配或冲突；宿主不实现字符串相似度、OCR 或页面业务规则。但只要模型承认
存在未解决冲突，`completed` 和 `business_data` 都不会被接受，并被保守转换成 `needs_input` 请
用户确认，而不是直接把会话判失败。旧
SQLite/JSON 会话由加载兼容逻辑使用原 `explanation` 补齐证据字段，不要求迁移用户数据。

### 3.3 页面模糊查询保留独立身份线索

Prompt 要求模糊查询不能把“小米良率上传”简单压缩成连续通用词“良率上传”。应在有界查询中保留
供应商/产品与业务功能等独立线索，例如两个参数化 `LIKE` 条件取交集。只命中通用功能但丢失区分
词的候选只能作为备选，不能直接完成；源码中没有区分词也不能证明用户把候选当作别名。

本轮人工只读核验 SQL 证明：

- `NAME LIKE '%小米%' AND NAME LIKE '%良率%'` 唯一命中“小米良率数据上传 / CustomYieldUpLoad”；
- `NAME LIKE '%良率上传%'` 只命中“FC良率上传机型 / FCModelUpload”；
- 因此之前的错误来自查询词丢失身份线索，不是 Menu 表或项目路径失效。

### 3.4 搜索边界与 Token

继续拒绝 `**/*`、`**/*.cs` 等全库模式，但允许带明确候选子目录的扩展名 Glob，例如
`**/CKClient/**/*.cs`。目录 Grep 仍必须有文件过滤器和 1..100 的 `head_limit`，每轮 Glob/Grep
总数仍为八次，工作区边界不变。

`page_location` 要求优先精确文件 Glob、有限 Grep 和最多 200 行的身份局部 Read；验证页面后停止，
不读取整条业务链。完整 `diagnosis` 不受这个深度限制，仍可沿最小相关调用链调查。

## 4. 真实验收

### 4.1 页面定位错误复现

一次实测只用“良率上传”连续词，Menu 返回 `FCModelUpload`。模型读取其源码后错误宣称该页面是“小米
良率上传”。本轮明确判定失败，没有把低 Token 结果视为优化成功。

### 4.2 修复后稳定结果

最终实测使用当前配置的 MES 测试工作区，输入只要求确认“小米良率上传”的页面、路由和源码：

- 精确查询 0 行；有界组合模糊查询命中“小米良率数据上传”；
- 菜单 URL、命名空间、类名、窗体标题和小米上传接口共同确认 `CustomYieldUpLoad`；
- `completion_kind=page_location`，`unresolved_conflicts=[]`；
- 0 条业务数据 SQL，0 个失败 Runtime，3 个 Runtime 轮次；
- 最终一次 Usage：输入 24,279、输出 4,197、缓存读取 65,408、12 turns、48.7 秒、约 0.259 美元；
- 相比同规则调整前的正确结果输入 35,990，减少约 32.5%。模型响应时间和输出 turns 仍有优化空间。

### 4.3 其余基础验收

- 截图标准化、发送、缺少页面标题时追问、补充标题后继续同一会话：真实通过；
- 完成后续聊：真实使用同一 session 新 cycle，0 次新 SQL，能够基于已有证据回答；
- Recovery：开发 inspect/implement/verify 与异常 inspect 的孤儿 Run 均通过 SQLite 重启扫描测试；
  启动不会自动重放模型，有副作用可能时进入 `recovery_required`，只读中断进入 `paused`；
- 桌面 `start.ps1` 可启动；当前 Codex 运行环境没有原生应用控制表面，无法代替用户完成鼠标按钮验收，
  因而不虚报点击结果。
- 自动化回归：221 passed；Ruff、`compileall`、`git diff --check` 均通过。

## 5. 决策与回退

- ADR-153：完成协议区分页面定位与完整诊断，任务深度由模型按语义选择；
- ADR-154：宿主固定页面证据/冲突完整性，不规定模型的调查步骤；
- ADR-155：模糊页面映射保留独立身份线索，通用功能候选不能覆盖冲突；
- ADR-156：明确候选子目录的扩展名 Glob 可用，全库扩展名扫描继续禁止；
- ADR-157：页面定位用局部源码证据控制 Token，完整诊断保留深入调查能力。

发布目标为 `v0.7.16`；上一稳定点为 `v0.7.15`。本轮没有 SQLite Schema 或业务数据迁移，回退只需
恢复完成类型、页面证据字段、Prompt、搜索策略及对应 UI/测试/文档。
