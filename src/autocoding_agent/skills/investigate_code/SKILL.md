# Investigate relevant code

Use this method after the goal is sufficiently clear.

1. Start with the file, path, symbol, behavior, or error supplied by the user.
2. Read the target before forming a conclusion.
3. Trace only relationships needed for the task: imports, callers, callees, configuration, tests,
   and data flow.
4. If the named target cannot be found, ask one question instead of guessing.
5. Ground the result in concise file evidence and distinguish facts from inferences.

Repository size is not permission to analyze the whole project. Expand scope only when evidence makes
the dependency relevant.
