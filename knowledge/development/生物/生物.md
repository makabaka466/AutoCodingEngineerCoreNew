# 指纹 MES 开发基础知识

> 本文只适用于当前配置的项目工作区。所有文件均以工作区相对路径表示；如果磁盘上存在同名
> 历史目录，以客户端当前选择的工作区为准，修改前必须再次核对仓库根目录和 `git status`。

## 项目定位

- 主解决方案：`QTMES.sln`。
- 技术主体：.NET Framework、WinForms、EF6 的 MES 单体解决方案，同时包含旧 Web、Web API、
  报表和较新的独立 API 子项目。
- 当前主要客户端：`MESClient/MESZWClient.csproj`，入口为 `MESClient/Program.cs`，输出类型为
  `WinExe`。
- 客户端启动会做单实例检查、注册 Autofac 服务并打开登录窗口。服务无法解析时，优先核对
  `MESClient/Program.cs` 的容器注册。
- 连接信息主要来自 `MESClient/App.config`。连接串、账号和密码是环境配置，不得进入源码、
  能力文档、日志或提交记录。

## 高优先级：从页面名称定位代码

当用户给出页面名称但没有源码路径时，优先通过共享只读数据库查询菜单映射，再按查询结果
缩小代码搜索范围。建议使用参数化查询：

```sql
SELECT NAME, URL
FROM Menu
WHERE NAME LIKE :page_name
```

参数 `page_name` 使用“用户给出的页面名称 + `%`”。结果中的 `URL` 是页面相对位置线索；它
不是最终事实，仍需在当前工作区中验证对应文件、路由和调用链。若当前 schema 与字段名不同，
先读取实际 schema，不要猜测，也不要拼接用户输入或改用写操作。

```text
QTMES.sln                      主解决方案
```

典型数据写入链路：

```text
MESClient 页面
  → QTMES.Application.Interface
  → QTMES.Application
  → QTMES.Core（IRepository / IUnitOfWork）
  → QTMES.Infrastructure（EFDbContext / Repository / UnitOfWork）
  → 数据库
```

- 数据库实体通常位于 `QTMES.Model/Entities`，命名空间为 `QTMES.Model.Entities`。
- 服务接口项目中沿用了 `Serivce` 的历史拼写；新增代码优先保持现有命名风格，避免无关重命名。
- 业务服务常拆成 partial 文件，例如 `QTMES.Application/Others/OtherSerivce.*.cs`。新增插入逻辑
  通常通过 `Repository.Insert(...)` 后调用 `UnitOfWork.Commit()`。
- EF6 上下文位于 `QTMES.Infrastructure/Data/EntityFramework/EFDbContext.cs`。新增实体时核对
  `DbSet` 和 `OnModelCreating` 映射注册。

## 当前重点：自定义良率上传

优先阅读这些文件及其直接依赖：

- `MESClient/CKClient/CustomYieldUpLoad.cs`
- `MESClient/CKClient/CustomYieldUpLoad.Designer.cs`
- `MESClient/MESZWClient.csproj`
- `QTMES.Model/Entities/Others/YIELDUPLOAD_LOG.cs`
- `QTMES.Application/Others/OtherSerivce.YieldUploadLog.cs`
- `QTMES.Application.Interface/IOthersSerivce.cs`
- `QTMES.Application/Others/OthersSerivce.cs`
- `QTMES.Infrastructure/Data/EntityFramework/EFDbContext.cs`

当前行为和约束：

1. 日期加载窗口是所选日期前一天 08:00 至所选日期 08:00；`data_lines` 使用记录条数。
2. 上传根对象的 `supplier_model` 来自查询结果中的 `WorkShop_Code`。
3. `key_code` 查询后只编辑内存缓存 `pendingData`，不会立即写入业务表。
4. `FCDataList.mep_def_array` 初始为空；用户新增明细后才产生可编辑、可删除的空行。
5. 新增明细会参考 `FCAPIController.GetFCYiledList`，用首笔 `Ecg_Code` 默认填充一级故障码及描述。
6. 不良明细区由 `groupBoxKeyQuery` 与接口主键查询区隔离，修改 Designer 时避免重新重叠。
7. 提交按每条 `FCDataList` 生成一条上传日志；每条日志包含共享根字段和当前 data，结果字段
   保存同一次上传结果。

### 外部上传仍处于测试状态

`CustomYieldUpLoad.cs` 中真实 `SendYieldPost(...)` 调用当前被注释，提交结果暂写为
`testUpLoad`。恢复真实上传前必须确认接口地址、认证方式、请求体和返回 JSON 格式，并在测试
环境联调；不得直接把测试状态代码当作生产上传。

### 上传日志字段边界

`YIELDUPLOAD_LOG` 的关键限制是：`CONTENT` 为 `nvarchar(1000)`，`RESULT` 与 `MUSER` 为
`nvarchar(50)`，`MDATE` 为日期。即使一条 data 写一条日志，JSON 仍可能超过 `CONTENT`。
如采用截断必须得到业务确认；如要求完整报文，应先调整数据库字段和实体映射。

## 修改与验证规则

- 固定布局改 `.Designer.cs`，事件和业务逻辑改 `.cs`；新增控件同时检查字段声明、初始化、
  事件绑定和项目文件包含关系。
- 老项目编码敏感，不要用批量格式化或整体重编码工具处理窗体、资源和中文注释。
- UI 修改后至少构建 `MESClient/MESZWClient.csproj`，并在可运行环境检查重叠、锚定和滚动。
- 推荐相对路径构建：

```powershell
MSBuild.exe .\MESClient\MESZWClient.csproj /t:Build /p:Configuration=Debug /m:1 /v:q
```

- 构建可能有历史依赖或警告；先判断是否由本次修改引入，不要顺手扩大任务。
- 开始前执行 `git status --short`，只暂存本次源文件。不要使用 `git reset --hard`，不要批量
  清理未知的 `bin/`、`obj/` 或用户变更。

## 推荐接手顺序

1. 以当前工作区打开 `QTMES.sln`，优先关注客户端、Model、Application 和 Infrastructure。
2. 阅读良率上传页面及 Designer，确认 UI、缓存和事件绑定的当前状态。
3. 核对上传日志实体、DbContext、服务接口与实现是否和实际数据库一致。
4. 在测试环境验证日期加载、key 查询、明细增删改、缓存回显和日志写入。
5. 只有外部接口信息与联调结果明确后，才提出恢复真实 HTTP 上传的方案。
